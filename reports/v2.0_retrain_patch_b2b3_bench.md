# v2.0 — Re-train trên data vá B2/B3 + re-bench (model)

- **Ngày:** 2026-06-06
- **Model:** `vi-rewriter` LoRA **train_v2** (Qwen2.5-1.5B-Instruct + 1000 mẫu vá B2/B3, 17001 mẫu) vs Qwen base | **Bench:** `data/bench/dialogues_bench_browser.jsonl`, n=1044
- **Judge:** `gpt-oss:120b-cloud` (Ollama, OpenAI-compat) — **đóng băng**, giống v1.0 → so chéo version hợp lệ. `judge_error_rate = 0%`.
- **Động cơ:** v1.3 vá data hẹp cho `multi_turn_slot` (pattern yếu nhất 52.8%). Train lại → đo xem patch có kéo pattern đích mà KHÔNG tụt các pattern khác.

## Đã làm

1. Train lại trên Kaggle với `train.jsonl` đã chèn patch B2/B3 (cell 5b, `patch_b2b3 --inplace`), hyperparams giữ nguyên. Adapter push lên `ThaoDuongDoingStuff/qwen-vi-rewriter-lora`.
2. Serve LoRA qua vLLM+ngrok. **Sửa `MAX_MODEL_LEN` 2048 → 8192** (`kaggle_serve.ipynb` + `kaggle_run.ipynb`): prompt baseline (40 few-shot) ~4.4k token, ở 2048 baseline lỗi `400 context length` 100%.
3. **Predict** (Kaggle vLLM, `--no-judge`) rồi **judge** (local, `--resume`) tách 2 bước. Judge đứt giữa chừng do Ollama rớt → 32 dòng `__JUDGE_ERROR__`, quét lại bằng `--resume` (idempotent) → 0 lỗi.
4. Output: `data/bench/eval_results/full_v2_gptoss/`.

## Kết luận

1. **Patch B2/B3 thành công, có mục tiêu:** kéo pattern yếu nhất `multi_turn_slot` 52.8→57.1 (+4.3) và `implicit_reference` +3.1, **không** làm tụt command-acc tổng (phẳng −0.3).
2. **Negation vẫn là điểm yếu chưa giải quyết:** LoRA (A4-corrected) giữ nguyên **81.5%** = đúng số v1.0 (patch không nhắm negation). Mức hồi quy canonical vẫn **−6.7đ** vs base v1.0 (88.2); gap v2.0 nhỏ lại (−0.9) chỉ vì baseline tệ đi do đổi pool few-shot. Cần bước riêng (oversample negation đã được khuyến nghị tránh ở [[train-data-not-the-bottleneck]] → ưu tiên model lớn hơn).
3. `code_switching` −4.6 cần soi xem là nhiễu hay regression thật.

## ⚠️ Caveat đọc số baseline

Baseline dùng **20 few-shot random từ `train.jsonl`**; v2.0 đã vá `train.jsonl` → pool few-shot đổi → điểm *baseline* dao động giữa các lần chạy (vd `negation_preservation` base 84.9%→78.2%, command-acc base 52.8%→53.6%). **So LoRA-với-LoRA across version đáng tin; số baseline chỉ nên đọc trong cùng một lần chạy.**
